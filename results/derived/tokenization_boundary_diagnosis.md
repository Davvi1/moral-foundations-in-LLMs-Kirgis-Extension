# Why the v2 scorer was rewritten: two defects in v1's probability readouts

Generated by `scripts/diagnose_boundaries.py`. Both defects were found while
**testing** the v2 scorer, not while analysing results. Neither raised an error;
neither produced an obviously wrong number. That is the point.


## D1 — v1 mixed two tokenizations and assumed they agreed

v1 located the option's first token at `len(local_tok.encode(prompt,
add_special_tokens=False))` and applied that index to the id sequence **vLLM**
returned. Nothing forces those to agree. Where a chat template already emits a
BOS token *and* the tokenizer adds another, the local count is one short.

**Consequence, and it is not uniform across the two normalisations.** The
off-by-one adds the *last prompt token's* logprob to every option's sum. Under
a plain sum that is a shared constant and cancels exactly in the softmax. Under
**length normalisation it does not cancel** — it adds a constant to the
numerator while the denominator goes from `n_k` to `n_k + 1`, and option token
counts are unequal. v1 ran `run_string(..., length_normalise=True)`
(`run_experiment.py:222`), so this is the arm that was exposed.

No roster tokenizer merges across the join on this prompt (all shifts 0), so
the BOS mismatch — not non-concatenativity — is the operative defect.


### The internlm case, and a correction to my earlier account

I previously attributed internlm2_5-7b-chat's 116/116 string failure to a
tokenizer merging across the join. **That is falsified**: its tokenizer is
concatenative on this prompt (shift 0, all three surface forms). Its rows show
`n_options_found = 0` and `logprob_mass` exactly `0.0`, which is the signature of
v1's `len(ids) <= n_base` guard firing — vLLM's tokenization was *shorter* than
the local one, not merely offset by one. **The exact cause is unverified** and
needs the pod to settle. v2 does not depend on settling it: it measures the
boundary between two id sequences vLLM itself produced, so the whole
local-vs-engine class disappears rather than being diagnosed.


## D2 — v1's string 'retained mass' was never a probability

`expectation()` computes `mass = sum(exp(v))` over whatever scores it is given.
v1 handed it **length-normalised** scores, i.e. per-token *mean* logprobs. So
v1's string mass is a sum of **geometric means**, with no probabilistic reading.
Label scoring handed the same function raw logprobs, where the result *is* a
probability. The two columns share a name and a scale and measure different
things.

Worked example, one plausible item (totals −6.0/−5.4/−4.8/−3.2/−5.0 over
4/3/3/2/3 tokens):

| quantity | value |
|---|---:|
| sum of raw sequence probabilities (a probability) | 0.0627 |
| sum of exp(per-token mean logprob) — what v1 logged | 0.9811 |
| (check: raw sum recomputed directly) | 0.0627 |

**What this invalidates.** METHODOLOGY_REVIEW.md F1 argued that string scoring
was mismeasuring partly because it 'retained mass 0.22 against label's 0.81'.
**That comparison is withdrawn** — the numbers are not commensurable, and a low
value is the expected magnitude for a sum of five geometric means. The error was
mine.

**What survives.** F1's *other* leg is untouched and is an independent
observation from generated text: asked this question with the options displayed,
models write `3: Very wrong`, not `Very wrong`. That still motivates scoring the
full option line, and P1/P2 still test it. F1 now rests on one argument rather
than two, and the surviving one is the stronger of the pair.

**What v2 changes.** The primary score is the logsumexp of *raw* sequence
logprobs, so its mass is a genuine probability — a lower bound on 'the model
continues with one of the five option strings'. Label and string mass become
directly comparable for the first time. Length normalisation is kept, but only
as the recorded secondary (`score_alt_normalisation`).


## What to carry into the write-up

Neither defect is a reason to distrust the Phase-1 *headline*, and neither should
be inflated into one. The model × method interaction rests on all four arms, and
the two Kirgis actually confounded (label, sampled) are unaffected by D2 and
agree at rho = 0.88 regardless. What changes is narrower and worth stating
plainly: the string arm's ranking disagreement (rho = 0.332) was measured with a
probe of uncertain aim and, on 12 of 30 models, a boundary computed from the
wrong tokenizer. v2 re-measures it cleanly. If the disagreement survives, it is a
finding; if it does not, v1's string arm was an artifact and saying so is the
result.
